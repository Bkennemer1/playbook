<div className="step-page-section">
  <h2>Overview</h2>
  <p>The client needs list is the borrower's document request — the itemized list of what they need to upload, delivered by email with a link to the portal. Arive generates the basics automatically, but the auto-list is never complete. The real LO skill in this step is <strong>curating</strong>: reviewing what Arive generated and adding the custom needs it missed, based on everything you learned in the qualifying conversation and the AUS findings.</p>
</div>

<div className="step-page-section">
  <h2>Two generation paths</h2>

  <h3>Online application path — automatic</h3>
  <p>When the borrower finishes the online application, Arive auto-generates the needs list under the <strong>Client Needs</strong> tab and auto-emails it to the borrower. Zero LO action required to initiate — the borrower can start uploading immediately.</p>
  <p>But automatic doesn't mean complete. Go review the list (see curating below).</p>

  <h3>Phone application path — LO triggers it</h3>
  <p>Phone-taken applications don't auto-generate. The LO goes to the <strong>Client Needs</strong> tab and hits the <strong>auto-generate</strong> button, which builds the basics list and emails the client needs directly to the borrower so they can begin uploading.</p>
  <p><em>Scribe walkthrough pending — the Client Needs tab: auto-generating, and adding custom needs.</em></p>
</div>

<div className="step-page-section">
  <h2>Curating the list — where the value is</h2>
  <p>The auto-generated list covers basic documents. It regularly misses the file-specific needs — and every one of these comes up all the time:</p>
  <ul>
    <li><strong>Letters of explanation</strong> — job gaps, credit inquiries, address mismatches</li>
    <li><strong>Gift funds</strong> — gift letter and supporting docs</li>
    <li><strong>Divorce decree / child support orders</strong> — when income or obligations flow through them</li>
    <li><strong>Self-employed package</strong> — business returns, P&amp;L, business bank statements</li>
    <li><strong>REO documentation</strong> — mortgage statements, leases, tax and insurance for other properties owned</li>
    <li><strong>Contract addenda and amendments</strong> — anything modifying the purchase contract</li>
  </ul>
  <p>Your sources for what to add:</p>
  <ol>
    <li><strong>The qualifying conversation.</strong> Everything you learned that complicates the file — the rental property, the 1099 income, the divorce, the gift from mom — translates directly into a need you add now.</li>
    <li><strong>The AUS findings.</strong> The findings report spells out documentation requirements (covered in <a href="/phases/application/run-aus">Run DU/LP</a>). Check the doc requirements section and make sure the needs list matches.</li>
  </ol>
  <p>A curated list up front means one clean ask of the borrower. A lazy list means the borrower gets hit with "one more thing" requests for weeks — which erodes trust and slows the file.</p>
</div>

<div className="step-page-section">
  <h2>Automatic reminders</h2>
  <p>Arive automatically reminds borrowers about outstanding needs on a configurable cadence — same settings concept as the incomplete-application reminders. Set your cadence once in your Arive settings and the system nags for you. As with app reminders, these are email-only; a personal text still outperforms them when items stall.</p>
</div>

<div className="step-page-section">
  <h2>Common pitfalls</h2>

  <h3>Trusting the auto-list</h3>
  <p>The number-one mistake. Auto-generate is a starting point, not a finished request. If you learned something in the qualifying call that needs documentation, and it's not on the list, the file stalls at underwriting waiting for it.</p>

  <h3>Ignoring the AUS findings when building the list</h3>
  <p>The findings literally tell you what the file needs. A needs list that doesn't match the findings means collecting docs twice.</p>

  <h3>Front-loading nothing, back-loading everything</h3>
  <p>Every custom need you fail to add now becomes a mid-process ask later — usually discovered at handoff or, worse, at underwriting submission. Ask once, ask complete.</p>
</div>
