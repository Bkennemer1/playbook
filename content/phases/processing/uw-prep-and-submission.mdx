  <h2>Overview</h2>
  <p>Once file setup is done and the borrower's documents are in, Danielle packages the file and submits it to underwriting. This is the last back-office step before the file leaves for a UW decision — the goal is a clean, complete, organized package that comes back approved with as few conditions as possible.</p>
</div>

<div className="step-page-section">
  <h2>The compliance scrub</h2>
  <p>Before submission, Danielle does a <strong>quick organization pass</strong> over the full file — confirming everything is present, current, and in order. This is a lighter check than it once was, by design: <strong>Hunter's Pre-Underwriting Review already caught the document-level issues</strong> (missing pages, stale paystubs, ID problems, asset gaps) on the borrower-facing side. Danielle isn't re-doing Pre-W; she's confirming the assembled package is complete and ready to submit.</p>
  <p>If Pre-W was done well, this is fast. If something slipped through, this is the last catch before underwriting sees it.</p>
</div>

<div className="step-page-section">
  <h2>Submitting to underwriting</h2>
  <p>The submission is a manual package-and-upload:</p>
  <ol>
    <li><strong>Download all documents from Arive</strong> — the full file.</li>
    <li><strong>Assemble the PDF package</strong> and <strong>upload it to the lender portal</strong> for submission.</li>
    <li><strong>Update Arive to reflect Submitted to UW.</strong></li>
  </ol>
  <p><em>Scribe walkthrough pending — downloading the Arive doc set and building the submission package.</em></p>
</div>

<div className="callout warn">
  <strong>Update the Arive milestone to Underwriting Submitted.</strong> Same discipline as every other milestone in this playbook — the internal pipeline tools key off it. In the pipeline queue, marking the "Submit file to underwriting" task done is what moves this file out of Danielle's New Files queue, so the milestone and the task completion need to reflect reality. A file submitted to UW but still showing an earlier milestone is a file the system thinks is still sitting in processing.
</div>

<div className="step-page-section">
  <h2>What happens next</h2>
  <p>The file is with underwriting. What comes back — almost always — is an <strong>Approved with Conditions</strong> decision: the underwriter approves the loan subject to a list of conditions that have to be cleared. That kicks off <a href="/phases/uw-decision/awc-trigger">the next phase</a>, where the conditions get split between Hunter (borrower-facing) and Danielle (back-office) and worked until the file is clear to close.</p>
  <p>While the file is in UW review, there's nothing for Danielle to actively do on it — the file sits in underwriting's hands. Inbound items that arrive during this window (title work, the appraisal, HOI binder) get handled email-first and uploaded to Arive as they come in.</p>
</div>

<div className="step-page-section">
  <h2>Common pitfalls</h2>

  <h3>Submitting an incomplete package</h3>
  <p>A package missing documents comes back with conditions that are really just "you forgot to include X" — avoidable rework that adds a full UW cycle. The scrub exists to prevent this.</p>

  <h3>Forgetting the milestone update</h3>
  <p>Submitted to UW but milestone unchanged means the file looks stuck in processing to everyone watching the pipeline, and it doesn't leave Danielle's queue.</p>

  <h3>Disorganized package</h3>
  <p>An underwriter who has to hunt for documents in a messy package works slower and asks more questions. Clean, ordered submissions get cleaner, faster decisions.</p>
</div>
