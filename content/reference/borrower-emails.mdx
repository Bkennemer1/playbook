<div className="step-page-section">
  <h2>What this page is</h2>
  <p>Arive fires automated emails to borrowers at loan milestone changes and certain tracker events. These are <strong>automatic</strong> — the status change sends the email. Nobody hits send.</p>
  <p>This page is the complete catalog: every automated borrower email, what triggers it, who receives it, and its full content. Read the email for a milestone before you move a file into it — the borrower is about to receive it, so the file had better be right first.</p>
</div>

<div className="callout warn">
  <strong>Milestone changes are borrower-facing events.</strong> Flipping a status in Arive isn't internal bookkeeping — it sends mail to the borrower, their co-borrower, their agent, and others. Don't advance a milestone to tidy your pipeline view, and never advance one before the thing it announces is actually true.
</div>

<div className="callout warn">
  <strong>Two known issues in the current templates — flagged for fixing:</strong>
  <br /><br />
  <strong>1. Possible duplicate review request.</strong> The Google review ask is built into the <strong>Loan Funded</strong> email, which is the right place — the loan has actually funded. But a separate "Loan Closed – Congratulations!" review email has also been seen firing at <strong>Docs Signed</strong>, which is premature (the loan hasn't funded yet, and the subject line says "closed" when it hasn't). If both are active in Arive, borrowers get asked for a review twice. The Docs Signed review request should be retired; the review ask belongs only on Loan Funded.
  <br /><br />
  <strong>2. "EaseDocs" is hardcoded in two emails.</strong> The Loan Setup and Disclosed emails both name EaseDocs as the e-sign system. EaseDocs is UWM-specific — every other lender uses a different one. A non-UWM borrower is told to watch for an EaseDocs email that never arrives. Until these are made lender-aware, tell non-UWM borrowers which e-sign system to actually expect.
</div>
